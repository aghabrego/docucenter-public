⚡ API ACI Cloud con Emisión Síncrona

📋 Descripción General

La API ACI Cloud con Emisión Síncrona es una nueva implementación que combina la creación de ventas ACI Cloud con la emisión inmediata de facturación electrónica, proporcionando confirmación en tiempo real del resultado completo del proceso.

⭐ Características Principales

  • ✅ Procesamiento Síncrono: Espera el resultado completo de la emisión antes de responder
  • ✅ Confirmación Inmediata: Retorna el estado final de la facturación electrónica
  • ✅ Reutilización de Código: Usa servicios existentes sin duplicar lógica
  • ✅ Control de Reintentos: Máximo 2 intentos automáticos por documento
  • ✅ Auditoría Completa: Tracking detallado para seguimiento operacional
  • ✅ Compatibilidad Total: Misma estructura de datos que APIs existentes

🔗 Endpoint Principal

POST /api/v1/fe/create_sale_acicloud_with_emission
Content-Type: application/json
Authorization: Bearer {token}

🔄 Comparación de APIs

API Comportamiento Retorna Uso Recomendado
/create_sale_acicloud ⚡ Asíncrono - Job en background Confirmación inmediata Procesamiento masivo/batch
/create_sale_acicloud_without_issuing ⚡ Asíncrono - Solo guarda, no emite Confirmación inmediata Solo guardar para revisión
/create_sale_acicloud_with_emission ⏱️ Síncrono - Espera resultado completo Resultado de emisión Integración ERP/POS tiempo real

✅ Funcionalidades

1. Procesamiento Síncrono

  • ✅ Procesa la venta ACI Cloud inmediatamente
  • ✅ Espera a que complete la emisión de FE
  • ✅ Retorna el resultado completo incluyendo CUFE y estado
  • ✅ No requiere polling o webhooks para obtener el resultado

2. Reutilización de Servicios Existentes

  • ✅ Usa ACIcloudService existente (sin duplicar código)
  • ✅ Mismas validaciones que el Job asíncrono
  • ✅ Misma lógica de emisión de FE
  • ✅ Compatibilidad total con estructura de datos existente

3. Tracking y Auditoría

  • ✅ Almacena transacción para auditoría
  • ✅ Logs detallados del proceso completo
  • ✅ Control de reintentos: Máximo 2 intentos por documento
  • ✅ Manejo de errores específico y detallado

async function createSaleWithEmission() {
  try {
    const response = await fetch(url, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(data)
    });

    const result = await response.json();

    if (result.success) {
      console.log('✅ Venta creada y emitida exitosamente');
      console.log('ID Venta:', result.data.sale.id);
      console.log('Número Factura:', result.data.sale.invoice_number);
      console.log('CUFE:', result.data.emission.cufe);
      console.log('Estado:', result.data.emission.status);
    } else {
      console.log('❌ Error:', result.message);
      if (result.data?.emission?.errors) {
        console.log('Errores específicos:');
        result.data.emission.errors.forEach(error => {
          console.log(`  - ${error}`);
        });
      }
    }
  } catch (error) {
    console.error('Error de red:', error);
  }
}

🔍 Verificación de Intentos Previos

Antes de procesar una nueva solicitud, la API verifica:

  • 🔍 Número de documento no haya sido procesado previamente
  • 🔍 Contador de intentos no exceda el máximo permitido
  • 🔍 Estado de emisión del documento en la base de datos
  • 🔍 Registro de auditoría para tracking completo

🧪 Testing y Validación

📋 Casos de Prueba Recomendados

1. Caso de Éxito - Primera Emisión

  • 📝 Datos válidos según especificación DGI
  • 📝 Número de documento único
  • 📝 Estructura JSON completa y correcta
  • ✅ Resultado esperado: Emisión exitosa en primer intento

2. Caso de Error - Datos Inválidos

  • 📝 RUC inválido o formato incorrecto
  • 📝 ITBMS mal calculado
  • 📝 Campos requeridos faltantes
  • ❌ Resultado esperado: Error con detalles específicos

3. Caso de Reintentos

  • 📝 Primer intento con error temporal (ej: conexión DGI)
  • 📝 Segundo intento con datos corregidos
  • 📝 Tercer intento debe ser rechazado
  • ⚠️ Resultado esperado: Error de intentos excedidos

4. Caso de Documento Duplicado

  • 📝 Mismo número de documento enviado múltiples veces
  • 📝 Verificación de estado existente
  • 🔄 Resultado esperado: Manejo apropiado según estado anterior
