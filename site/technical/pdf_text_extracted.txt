1 Introducción
En este documento analizaremos y propondremos una solución para la implementación de la Facturación Electrónica en
Colombia.
1.1 Definiciones y Abreviaciones
1.1.1 Definiciones
- Adquirente: El adquiriente es el que “adquiere” o realiza la compra y recibe el servicio. En nuestro caso el
usuario final del parking.
- Integrador: Es un proveedor tecnológico habilitado para generar, entregar y/o transmitir la factura electrónica
que cumpla con las, condiciones y requisitos que señale la DIAN.
- SIENA: Integrador utilizado por Unicentro Cali y el distribuidor SIMAT.
- BTW: Integrador utilizado por cliente y el distribuidor Logtech.
1.1.2 Abreviaciones
- CO: Colombia.
- CUFE: código único de facturación electrónica.
- DIAN: Dirección de Impuestos y Aduanas Nacionales.
- DEE: Documento Equivalente Electrónico.
- ES: España.
- PK: Parking.
- SC: Sistema de Control.
- UT: User Terminal. Terminal de Usuario.
- TP: Terminal de Pago.
- TPA: Terminal de Pago Automático. Cajero automático.
- TPM: Terminal de Pago Manual. Caja Manual.
- TP-Virtual: TP Virtual ejecutado en el servidor de parking.
- MTPM: Mobile TPM. Terminal de pago sobre App o Tablet.
1.2 Sumario
Es el siguiente:
- Capítulo 1: introducción y definiciones.

2.3 Desarrollo Propuesto
2.3.1 Flujo de Operación
2.3.1.1 Secuencias de emisión de comprobante configurables
Con el objetivo de acelerar al máximo el proceso de generación de comprobante y de flexibilizarlo a los requerimientos
del cliente se ha hecho configurable operar con los comprobantes de la siguiente manera:
- Con/Sin documento equivalente: El TP podrá operar sin emitir DEE de forma que se pase directamente a
utilizar solo factura anónima o nominal. Esto permite eliminar la etapa de selección entre documento
equivalente y factura.
- Comprobante Si/No Imprimir obligatoriamente: en este caso se puede configurar si el comprobante se debe
imprimir de forma obligatoria. En caso de que sea No, se preguntará al usuario si desea imprimir el
comprobante o no.
- Reintentar vs Comprobante Anónimo: Si falla el registro del comprobante nominal se podrá configurar si ante
el fallo del registro de un comprobante nominal se quiere volver a la pantalla de preguntar nominal o anónimo,
o por el contrario pasar directamente a emitir comprobante anónimo.
- Ante fallo registro comprobante anónimo, cancelar cobro vs emitir comprobante en contingencia: Ante el fallo
del registro de un comprobante anónimo o DEE, se podrá escoger por configuración si se quiere registrar el
comprobante en contingencia o si por el contrario se desea cancelar el cobro y marcar el comprobante como
anulado.
Nota: No olvidar que, aunque sea una factura nominal, si el endpoint de registro no responde, por timeout o por no
respuesta del servidor (error 404) se deberá registrar el comprobante nominal en contingencia.
2.3.1.2 Flujo de Operación Habitual
Entendemos como flujo de operación habitual el flujo que no genera ninguna incidencia y que permite registrar el
comprobante en la DIAN si inconvenientes.
2.3.1.2.1 Flujo Habitual con DEE y Factura a Imprimir Obligatorio
Mostramos el flujo de operación habitual para el caso en que se pueda escoger entre inicialmente entre DEE o Factura,
y en la siguiente pantalla Factura Anónima o Nominal. Además, para este caso, no se preguntará al usuario final si
quiere imprimir el comprobante o no.

2.3.1.3 Flujo de Operación Rechazada
El comportamiento de rechazo y contingencia de la versión previa de documento se ha redefinido. De forma que no hay
situaciones de contingencia o situación de rechazo, sino que ante un error sea del tipo que sea, se puede actuar de las
siguientes formas:
- Si es nominal ante fallo, se le puede indicar reintentar escoger la factura anónima/nominal o intentar emitir
directamente factura anónima.
- Si es anónima, se le puede indicar, cancelar cobro o registrar en contingencia.
Para el caso del DEE como siempre se trata de forma anónima ante fallo tan solo se podrá cancelar el cobro o registrar
en contingencia.
2.3.1.3.1 Factura Nominal con reintento
Tenemos 2 endpoints el de datos NIT y el de registro de comprobante.
- Endpoint de datos de NIT: En caso de rechazo se entenderá que el NIT no es válido y se volverá a la pantalla
de identificar NIT donde podrá reintentar con otro NIT, o pasar a generar el documento como consumidor
final.
o En caso de Timeout se volverá a la pantalla de reintento.
- Endpoint de registro de comprobante: En caso de rechazo, volveremos a la pantalla de selección de factura
nominal o anónima (contribuyente final).
o En la pantalla de reintento en caso de Timeout se intentará emitir factura anónima.

2.3.1.3.2 Factura anónima o DEE con cancelación de cobro
En este caso solo aplica el endpoint de registro de comprobante.
- Endpoint de registro de comprobante: En caso de rechazo, se cancela el cobro.
o En las pantallas de selección en caso de timeout se intenta enviar el comprobante anónimo.
2.3.1.3.3 Factura anónima o DEE con aceptación en contingencia
El tratamiento de contingencia se basa que en caso de error de registro de comprobante (del tipo que sea) nosotros
continuamos con el cobro emitiendo un comprobante de contingencia (comprobante de emergencia).
Luego la petición de este comprobante se manda al servidor donde un servicio de tipo timer hace reintentos de registro
de comprobante cada X tiempo.
El mecanismo de contingencia se planteó inicialmente para los casos en los que no hubiese comunicación con el
facturador externo, pero actualmente se ha visto como un mecanismo útil para no detener el cobro en un TP ante
cualquier tipo de error.
En todo caso, debe tenerse presente que la petición de registro queda pendiente y se reintenta de forma sucesivas. En
caso de un problema no resoluble automáticamente el comprobante terminará por no registrarse nunca en la DIAN.
Como en el caso anterior solo vamos a revisar el registro del comprobante.

- 3 - Error Solicitud invalida: Error generar de solicitud no válida.

registrado en la DIAN previamente. Actualmente se describe como “Documento emitido previamente”.

(secuencia) superior al último + 1. Por ejemplo, el último DEE registrado es el 100, se intenta registrar el 105,
