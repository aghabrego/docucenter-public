    API Customer Receipt - Recibos de Pago

    🧾 CustomerReceiptImpRequest - Validaciones

    API para gestión de recibos de pago de clientes con validaciones avanzadas, soporte para prepagos, aplicación a facturas existentes y productos/servicios nuevos.

    🎯 Descripción General

    La API de Customer Receipt maneja recibos de pago de clientes basada en las tablas customer_receipt_header_imp y customer_receipt_detail_imp, con validaciones complejas según el tipo de operación.

    Características Principales

    • 💰 Prepagos: Soporte completo para pagos por adelantado y devoluciones
    • 📋 Aplicación a Facturas: Vinculación de pagos a facturas existentes
    • 🛍️ Productos/Servicios: Creación de nuevos items en el recibo
    • 🔄 Validación Condicional: Lógica de validación dinámica según contexto
    • ✅ Validaciones Exhaustivas: Controles estrictos según reglas de negocio

    📋 Estructura de Datos

    Request Principal

    "CustomerReceiptImpRequest": "app/Http/Requests/CustomerReceiptImpRequest.php"

    Tablas de Base de Datos

    • Header: customer_receipt_header_imp
    • Detail: customer_receipt_detail_imp

    🏠 Validaciones Header

    Campo Tipo Validación Descripción
    Reference string required, max:40 Referencia del recibo
    CheckNumber string required, max:20 Número de cheque
    ReceiptNumber string required, max:20 Número de recibo
    ParentTransactionId integer nullable, exists:SalesHeaderImp,ID ID de transacción padre
    CustomerID string required, max:20 ID del cliente
    CustomerName string required, max:39 Nombre del cliente
    Total numeric required, 0-99999999999999.99 Total del recibo
    Method_of_Payment string required, max:20 Método de pago
    TaxID string nullable, max:8 ID fiscal
    SalesRepID string required, max:20 ID del representante
    Date date nullable Fecha del recibo
    CashAccountID string required, max:15 Cuenta de efectivo
    Prepayment boolean nullable Es prepago
    DepositTicketID string nullable, max:8 ID del ticket de depósito

    ⚠️ Campo Crítico

    CashAccountID es REQUERIDO (cambió de nullable a required) con máximo 15 caracteres según el stub de base de datos.

    📦 Validaciones Items

    Campo Tipo Validación Descripción
    Items array required Array de items del recibo
    Items.*.ApplyTo boolean required Si se aplica a factura
    Items.*.InvoiceNumber string required_if:ApplyTo,true Número de factura (si ApplyTo=true)
    Items.*.Description string required, max:160 Descripción del item
    Items.*.Net_line numeric required, 0-99999999999999.99 Monto neto
    Items.*.Quantity numeric required_if:ApplyTo,false Cantidad (si ApplyTo=false)
    Items.*.Item_id string nullable, max:20 ID del producto
    Items.*.Unit_Price numeric required_if:ApplyTo,false Precio unitario (si ApplyTo=false)
    Items.*.Taxable integer nullable Es gravable

    🔄 Lógica Condicional

    La validación de campos en Items depende de dos factores principales:

    1. Prepayment (a nivel de header)
    2. ApplyTo (a nivel de item)

    🔹 PREPAYMENT = true (Pago por adelantado)

    💡 Características de Prepagos

    • Quantity: OPCIONAL - Puede ser null
    • Item_id: OPCIONAL - Puede ser null
    • Unit_Price: OPCIONAL - Puede ser null
    • Net_line: PUEDE SER NEGATIVO - Permite devoluciones/ajustes
    • Total: PUEDE SER NEGATIVO - Permite devoluciones
    • InvoiceNumber: Depende de ApplyTo

    🔹 PREPAYMENT = false + ApplyTo = true (Aplicar a factura existente)

    • InvoiceNumber: REQUERIDO - Debe especificar factura
    • Quantity: OPCIONAL - No necesario para aplicar a factura
    • Item_id: OPCIONAL - No necesario para aplicar a factura
    • Unit_Price: OPCIONAL - No necesario para aplicar a factura

    🔹 PREPAYMENT = false + ApplyTo = false (Producto/servicio nuevo)

    • InvoiceNumber: OPCIONAL - No aplica a factura existente
    • Quantity: REQUERIDO - Cantidad del producto/servicio
    • Item_id: OPCIONAL - ID del producto (nullable)
    • Unit_Price: REQUERIDO - Precio unitario del producto/servicio

  "Items": [{
    "ApplyTo": false,

    "Item_id": null,
    "Unit_Price": null

    🧪 Casos de Prueba

    ✅ Casos Válidos

    1. Prepago Positivo

    Prepayment=true, campos opcionales null

    {
  "Prepayment": true,
  "Items": [{
    "ApplyTo": false,
    "InvoiceNumber": null,
    "Quantity": null,
    "Unit_Price": null
  }]
}

    2. Devolución Prepago

    Prepayment=true, montos negativos

    {
  "Prepayment": true,
  "Total": -15.50,
  "Items": [{
    "Net_line": -15.50,
    "Quantity": null,
    "Unit_Price": null
  }]
}

    3. Aplicar a Factura

    Prepayment=false, ApplyTo=true, con InvoiceNumber

    {
  "Prepayment": false,
  "Items": [{
    "ApplyTo": true,
    "InvoiceNumber": "FE001",
    "Quantity": null,
    "Unit_Price": null
  }]
}

    4. Producto Nuevo

    Prepayment=false, ApplyTo=false, con Quantity y Unit_Price

    {
  "Prepayment": false,
  "Items": [{
    "ApplyTo": false,
    "Quantity": 2,
    "Unit_Price": 25.0
  }]
}

    ❌ Casos Inválidos

    1. Reference Vacío

    Debe fallar (required)

    2. ApplyTo=true sin InvoiceNumber

    Debe fallar (required_if)

    {
  "ApplyTo": true,
  "InvoiceNumber": null // ❌ Falla validación
}

    3. Producto sin Quantity/Unit_Price

    Prepayment=false, ApplyTo=false sin campos requeridos

    {
  "Prepayment": false,
  "Items": [{
    "ApplyTo": false,
    "Quantity": null, // ❌ REQUERIDO
    "Unit_Price": null // ❌ REQUERIDO
  }]
}

    4. CashAccountID Vacío

    Debe fallar (required)

    5. CustomerName >39 chars

    Debe fallar (max:39)

    💡 Reglas de Validación Clave

    1. required_if:Items.*.ApplyTo,true: InvoiceNumber requerido cuando ApplyTo=true
    2. Prepayment=true: Flexibiliza validaciones, permite valores negativos
    3. CashAccountID: Siempre requerido (máximo 15 caracteres)
    4. Lógica condicional: Quantity y Unit_Price dependen del contexto
